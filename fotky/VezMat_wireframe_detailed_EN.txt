VEZMAT – DETAILED WIREFRAME DESCRIPTION AND GAME FLOW LOGIC

This document describes each screen (node) in the wireframe and the full
transition logic between them. The system is structured as a hub-based
menu with a central gameplay loop.

  ---------------------------------------------------------------------
  SCREEN 1 – Login / Entry Screen
  ---------------------------------------------------------------------
  Purpose: Initial access point to the game.

  UI Elements: - Game title: “VezMat” - Button: Login - Button: Enter /
  Start - Possibly: Exit option

  Logic: - Login → Main Menu - Enter / Start → Main Menu - Exit →
  Application closes

  Notes: This screen acts purely as an authentication or entry gateway.
  No gameplay occurs here.
  ---------------------------------------------------------------------

SCREEN 2 – Main Menu

Purpose: Central navigation hub of the entire system.

UI Elements: - Button: Play - Button: Statistics - Button: Settings -
Button: Back / Logout

Logic: - Play → Tower / Floor Selection - Statistics → Statistics
Screen - Settings → Settings Screen - Back / Logout → Login Screen

This is a non-combat hub node. All major systems branch from here.

  ---------------------------------------------------------------------
  SCREEN 3 – Tower / Floor Selection
  ---------------------------------------------------------------------
  Purpose: Player selects a tower (topic) or difficulty path.

  UI Elements: - List of available towers (mathematical themes) -
  Difficulty indicators - Locked / unlocked status - Button: Continue -
  Button: Back

  Logic: - Continue → Intro Dialogue - Back → Main Menu

  Design Role: This screen defines the structure of progression. Each
  tower contains multiple floors. Each floor ends with a miniboss. The
  final floor ends with a boss.
  ---------------------------------------------------------------------

SCREEN 4 – Intro Dialogue (Wizard Explanation)

Purpose: Narrative introduction to the selected tower.

UI Elements: - Wizard character illustration - Dialogue bubble (general
explanation of combat and tower rules) - Button: Continue

Logic: - Continue → GAME (Main Gameplay Node)

Design Role: This screen establishes rules: - Enemies ask math
problems - Correct answers deal damage - Wrong answers cause player
damage - Player must clear rooms to progress

  ---------------------------------------------------------------------
  SCREEN 5 – Settings
  ---------------------------------------------------------------------
  Purpose: Modify gameplay parameters.

  UI Elements: - Sound toggle - Difficulty selection - Language
  selection - Button: Back

  Logic: - Back → Main Menu

  This is a detached configuration node.
  ---------------------------------------------------------------------

SCREEN 6 – Statistics

Purpose: Display player performance.

UI Elements: - Table of results - Floors completed - Enemies defeated -
Success rate - Button: Back

Logic: - Back → Main Menu

No gameplay transitions originate here.

  ---------------------------------------------------------------------
  SCREEN 7 – GAME (Core Gameplay Node)
  ---------------------------------------------------------------------
  Purpose: This is the central gameplay loop and most important state
  in the entire system.

  This node dynamically branches into multiple sub-states.

  Possible Room States:
  ---------------------------------------------------------------------

STATE A – Empty Room

Description: The player enters a room with no enemy.

UI: - Wizard short commentary - Continue button

Logic: Empty Room → GAME (Next Generated Room)

Function: Maintains pacing and unpredictability.

  -------------------------------------------------
  STATE B – Treasure Chest
  -------------------------------------------------
  Description: The player finds a chest.

  UI: - Chest illustration - Reward description -
  Confirm / Continue button

  Effects: - Player gains bonus (health, shield,
  damage boost, etc.)

  Logic: Treasure → GAME (Next Room)

  Function: Positive reinforcement and progression
  balancing.
  -------------------------------------------------

STATE C – Standard Combat

Description: A regular enemy appears.

UI: - Enemy character - Math problem displayed - Multiple choice
answers - Health indicators (player + enemy)

Combat Logic: Correct answer → Enemy loses HP Wrong answer → Player
loses HP

If enemy HP = 0: → Return to GAME (Next Room)

If player HP = 0: → Game Over Screen

Function: Core educational mechanic.

  -------------------------------------------------
  STATE D – Miniboss (End of Floor)
  -------------------------------------------------
  Trigger Condition: After a predefined number of
  rooms.

  Description: Stronger enemy with higher HP or
  multi-step problems.

  Logic: Correct answers → Damage miniboss Wrong
  answers → Player loses HP

  If miniboss defeated: → GAME (Next Floor Begins)

  If player defeated: → Game Over Screen

  Function: Marks completion of a floor.
  -------------------------------------------------

STATE E – Final Boss (End of Tower)

Trigger Condition: After completing final floor.

Description: Main tower antagonist. More complex math problems. Possibly
multi-phase combat.

Logic: If boss defeated: → Victory Screen

If player defeated: → Game Over Screen

Function: Completion milestone for the entire tower.

  ---------------------------------------------------------------------
  SCREEN 8 – Game Over
  ---------------------------------------------------------------------
  Trigger: Player HP reaches 0.

  UI Elements: - Defeat message - Button: Retry - Button: Return to
  Menu

  Logic: Retry → Restart Tower (Intro Dialogue or First Room) Return to
  Menu → Main Menu
  ---------------------------------------------------------------------

SCREEN 9 – Victory Screen

Trigger: Final boss defeated.

UI Elements: - Victory message - Tower completion confirmation - Button:
Return to Menu

Logic: Return to Menu → Main Menu

=====================================================================
GLOBAL SYSTEM FLOW
=====================================================================

Login → Main Menu → Play → Tower Selection → Intro Dialogue → GAME LOOP

GAME LOOP STRUCTURE: GAME → (Empty Room | Treasure | Combat) → GAME →
(after room threshold) Miniboss → GAME (Next Floor) → (after final
floor) Boss → Victory

Failure Path: Combat / Miniboss / Boss → Player HP = 0 → Game Over →
Retry OR Main Menu

Side Paths: Main Menu → Settings → Main Menu → Statistics → Main Menu

=====================================================================
DESIGN SUMMARY
=====================================================================

The system is built around a central procedural loop (GAME). All other
screens either: - Prepare the player (Menu, Selection, Intro), -
Configure the experience (Settings), - Display results (Statistics, Game
Over, Victory).

The educational mechanic (math combat) is embedded directly into every
combat state and scales with progression.

This structure allows: - Modular expansion (new towers), - Adjustable
difficulty, - Clear progression milestones (floor → miniboss → tower →
boss).
